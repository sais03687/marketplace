Release Notes test set

Four sandbox tests for the Release Notes agent, from easy to tricky. Each one has the exact text to paste, what a correct answer looks like, and what version 1.0.1 of the agent returned when it was run on 7 October 2026.

How to run one

  1. Copy a test's input with its Copy input button.
  2. Paste it as the whole message body: in the admin vetting "Test the agent" box, or in an email to a hired Release Notes agent.
  3. Compare the reply with What a correct answer does. The traps are the parts most likely to go wrong.
Order for the demo video: 1 · Sprint 2 · GitHub paste 3 · Context lines 4 · Nothing to announce
Test 1

Sprint release, conventional commits

Ran clean · use first

14 PRs from a task-management web app. Tests whether it sorts by what changed for users, not by the commit prefix.

1-saas-sprint.txt
Merged PRs for v3.8.0 (Taskflow web app), sprint ending Sept 26:

feat(boards): drag tasks between boards without opening them
feat(reports): weekly summary email for workspace owners, sent Monday 8am local time
feat(ci): add eslint step to PR pipeline

improve(mobile): task list no longer jumps to the top after marking something done
refactor(api): move task serializers into their own module
chore(deps): bump next from 15.2.1 to 15.3.0
docs: update CONTRIBUTING.md with branch naming rules
feat(export): export a board to CSV, including custom fields

What a correct answer does

  • New (3): drag between boards, weekly summary email, CSV export.
  • Improved (2): faster search, mobile list no longer jumps.
  • Fixed (3): due-date timezone, "remember me", duplicate mention emails.
  • Left out (6): feat(ci) despite the feat prefix, and fix: flaky test despite the fix prefix, plus refactor, deps, docs and test.

What it returned

  • All 8 notes in the right sections, rewritten for users ("Due dates are no longer shown one day early…").
  • All 6 internal PRs flagged.

What a correct answer does

  • SSO appears once, as New. The add, revert and re-land cancel out to one shipped feature. The redirect loop never reached users.
  • New: SSO, settings audit log, ? shortcut list.
  • Improved: dark-mode charts, bulk delete up to 500.

What it returned

  • The noise entries were flagged every time, quoted from the input. The two headings were not counted as PRs.
  • Slip: the v1 API removal moves between runs. It went under Improved in 2 runs, in the left-out list in 1, and under Fixed in 1. It is never called out as a breaking change.
Test 3

Mobile release with a context line per PR

Ran clean · 8 of 8 runs

12 PRs from a recipe app, most with a line of explanation. Tests whether it reads the context, for example that the nutrition panel is not shipping.

3-with-context-lines.txt
Release 2.11 - Pantry (recipe & meal planning app, iOS + Android)

#812 Shopping list: combine duplicate ingredients
  "2 eggs" from one recipe and "3 eggs" from another now show as "5 eggs". Different units (cups vs grams) are still listed separately.

#815 Fix crash when opening a recipe with no photo on Android 14
  Affected roughly 3% of Android sessions last week.

#817 Migrate image pipeline from Glide to Coil
  No visible change intended.

#819 Meal plan: copy last week's plan into this week
  One button on the week view. Doesn't copy the shopping list.

#820 Serving size slider now rounds to sensible amounts
  e.g. 1/3 cup instead of 0.333 cups; teaspoons round to nearest 1/4.

#821 Bump compileSdk to 35

#823 Fix: timers kept running after the recipe was closed, draining battery
  The notification now disappears when you leave the recipe.

#824 Analytics: add event for recipe_saved

#826 Nutrition panel
  Behind a feature flag, off for everyone. Not shipping in this release.

#828 Search understands "vegetarian", "vegan", "gluten-free" as filters
  Typing them in the search bar applies the filter instead of searching recipe titles for the word.

#830 Handle edge case in parser

#831 Offline mode: saved recipes open without a connection
  Only recipes saved after updating to 2.11; older saves need to be opened once online.

What a correct answer does

  • Notes (7): combined ingredients, Android 14 crash, copy last week's plan, rounded serving sizes, timers stopping, diet filters in search, offline saved recipes.
  • Keeps the limits the context lines give: different units stay separate, offline only covers recipes saved after updating.
  • Left out (5): Glide to Coil, compileSdk, analytics event, nutrition panel (flagged off), parser edge case.

What it returned

  • All 7 notes and the right 5 left-out PRs in every run, with the PR numbers quoted from the input.
  • Version 1.0.0 broke the left-out list in 2 of 3 runs. 1.0.1 numbers each entry, has the model answer by number, and quotes the input itself, so a garbled answer can no longer reach the reader and no entry can go unmentioned.
  • A garbled answer gets one automatic retry. If that fails too, the agent says so instead of guessing.
Test 4

Hotfix with nothing to announce

Ran clean · use as closer

6 internal PRs and no user-facing change. Tests whether it refuses to invent notes.

4-all-internal.txt
Hotfix 5.0.3 merged PRs:

chore: upgrade node 20 -> 22 in Dockerfile
ci: cache pnpm store between runs
refactor(db): extract connection pool config
test: fix timezone-dependent assertions
chore(deps-dev): bump vitest from 2.0.5 to 2.1.1
build: drop unused webpack alias

What a correct answer does

  • Writes no release notes.
  • Says plainly that nothing here changed for users, and lists what it left out.
  • Does not turn "fix timezone-dependent assertions" into a timezone fix for users.

What it returned

  • No notes, and a clear reason.
  • The reply no longer repeats the list. The internal PRs appear once, in the check list.

Still open in 1.0.1

  • Removals and breaking changes need their own section. Today they land in whichever section the model picks.
  • Under load the model sometimes takes over 120 seconds and the call times out.
  • The onboarding answers (product name, audience) are collected but never used in the notes.
